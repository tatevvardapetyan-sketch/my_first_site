What is A/B Testing?

A/B testing compares two versions of something (A vs. B) to see which performs better. You split your audience randomly, show each group a version, and measure a clear outcome (like clicks or purchases).

  • One clear goal metric
  • Random, fair split
  • Run long enough

When should I use it?

Use A/B tests for changes that could affect behavior: headlines, button labels, layouts, pricing messages, or onboarding steps.

Tip: If the change is tiny or the audience is tiny, A/B might not be worth the time—try user interviews instead.

What makes a good test?

  • Define success: e.g., “increase checkout completion.”
  • Form a hypothesis: “Shorter form will raise completion.”
  • Change one big thing: keep versions focused.
  • Decide test length: don’t end early because of a blip.
  • Keep traffic fair: random split, consistent targeting.

Do’s & Don’ts

Do

  • Pick one primary metric.
  • Run the test for full weeks (avoid weekday/weekend bias).
  • Document your hypothesis and version changes.
  • Share results—even if B didn’t “win”.

Don’t

  • Stop early because numbers look good for a day.
  • Test multiple big changes at once.
  • Change traffic targeting mid-test.
  • Over-optimize for a vanity metric.

Glossary (Tap to expand)

Conversion Rate (CR)
The percentage of visitors who complete the action you care about (e.g., purchase, sign-up).
Lift
How much better (or worse) B did vs. A. Report as absolute points and relative % change.
Variant
The new version you’re testing against the current version (control).
Primary Metric
The one metric that decides the test outcome. Keep it focused.
Run Time
How long the test should run to capture typical behavior (full weeks help reduce bias).

Pre-Launch Checklist

  1. Hypothesis is clear and tied to a metric.
  2. Tracking verified for all key events.
  3. Traffic split and audience rules locked.
  4. Test length agreed (don’t peek early).
  5. Success criteria defined (what counts as “ship it”).
  6. Comms owner assigned for sharing results.
